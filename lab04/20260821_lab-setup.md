# Windows 7 SP1 Lab — Fedora / KVM / libvirt / Metasploit

## Overview

This document records the complete setup and validation of an isolated Windows 7 Professional SP1 x64 virtual machine running on Fedora using KVM/libvirt.

The objective of the lab is to provide an isolated environment for security testing and vulnerability research against an intentionally vulnerable Windows 7 SP1 system.

The Windows 7 VM was successfully installed, configured with an isolated libvirt network, verified from the Fedora host, and tested with Nmap and Metasploit.

The MS17-010 vulnerability was detected successfully.

The EternalBlue exploit was **not executed**. A VM snapshot was created immediately before the exploitation stage so the machine can be restored to a known-good baseline.

---

## Host Environment

- Host OS: Fedora
- Virtualization: KVM/QEMU
- VM management: libvirt / virsh
- VM connection: `qemu:///system`
- GUI: SPICE
- Video: QXL
- Guest OS: Windows 7 Professional SP1 x64

## VM Creation

The VM was created with:

```bash
sudo virt-install \
  --connect qemu:///system \
  --name lab04-win7 \
  --memory 2048 \
  --vcpus 2 \
  --os-variant win7 \
  --boot loader=/usr/share/seabios/bios.bin,loader.readonly=yes \
  --disk path=/var/lib/libvirt/images/lab04-win7.qcow2,format=qcow2,bus=sata \
  --cdrom /var/lib/libvirt/images/pt_windows_7_professional_with_sp1_x64_dvd_u_676950.iso \
  --network network=lab-isolated,model=e1000 \
  --graphics spice \
  --video qxl
```

The initial `virt-install` invocation reported that `virt-viewer` was not installed:

```text
WARNING  Unable to connect to graphical console: virt-viewer not installed.
```

The VM was nevertheless successfully created and remained running.

`virt-viewer` was then installed:

```bash
sudo dnf install virt-viewer
```

The Windows 7 installation completed successfully.

## Windows Firewall Investigation

The Windows 7 firewall was inspected.

Both the Home/Work (Private) profile and the Public profile were enabled.

The firewall configuration was effectively:

```text
Private:
Enabled
BlockInbound, AllowOutbound

Public:
Enabled
BlockInbound, AllowOutbound
```

The relevant Windows Firewall rule for File and Printer Sharing was initially disabled.

The Windows firewall interface provides separate rule groups for the Home/Work profile and the Public profile.

File and Printer Sharing was enabled in both profiles for the purpose of this isolated lab.

After enabling File and Printer Sharing, the SMB-related ports became reachable.

## MS17-010 Vulnerability Detection

The MS17-010 scanner was executed:

```bash

  "use auxiliary/scanner/smb/smb_ms17_010; set RHOSTS 10.10.10.124; run; exit"
```

```text

Host is likely VULNERABLE to MS17-010!

Windows 7 Professional 7601 Service Pack 1 x64 (64-bit)
```

This provided strong evidence that the target was vulnerable to MS17-010.

This independently confirmed the previous MS17-010 scan.
